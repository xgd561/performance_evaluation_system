## 一、Admin 在系统中的主要工作

根据 PRD_绩效考核评分系统_v1.0.md，Admin 是系统的**最高权限角色**，核心职责覆盖系统配置、组织管理、数据治理、最终审批四大领域：

| 职责领域 | 具体工作内容 |
|---------|---------|
| **系统配置** | 考核周期管理、岗位 KPI 模板配置、维度权重设置、绩效等级规则（A/B/C/D 区间）、审批链配置、小部门豁免规则 |
| **组织管理** | 员工增删改查、部门管理（含树形结构与拖拽排序）、岗位管理、员工批量导入（Excel） |
| **数据治理** | 全公司汇总查看、报表导出（Excel/PDF）、已归档数据解冻修改、操作日志审计 |
| **最终审批** | 强制分布特批审批链的最后一级（当 HR 调整被驳回时，由 Admin/总经理最终裁决） |
| **权限与运维** | 角色权限分配、系统冷启动初始化、考核取消（任意活跃状态 → cancelled） |

## 三、逐场景深度审核

### 场景 S1：登录后仪表盘显示全局统计

**业务价值**：验证 Admin 登录后能看到**全公司级别**的数据概览，而非个人/团队视角。

#### 测试点与校验方式

| 序号 | 测试点 | 用例脚本中的校验方式 | 是否能发现 Bug |
|------|--------|-------------------|-------------|
| T1.1 | 登录成功并跳转仪表盘 | `await page.waitForURL('**/dashboard')` + `expect(page).toHaveURL(/.*\/dashboard/)` | ✅ 能发现登录失败、路由跳转异常 |
| T1.2 | 页面标题"仪表盘"可见 | `expect(page.getByRole('heading', { name: '仪表盘' })).toBeVisible()` | ✅ 能发现页面白屏、Vue 渲染失败 |
| T1.3 | 统计卡片"员工总数"可见 | `expect(page.locator('.stat-label').filter({ hasText: '员工总数' })).toBeVisible()` | ✅ 能发现仪表盘 API 异常、统计卡片未渲染 |
| T1.4 | 统计卡片"部门数量"可见 | 同上模式 | ✅ 同上 |
| T1.5 | 统计卡片"考核周期"可见 | 同上模式 | ✅ 同上 |
| T1.6 | 统计卡片"进行中"可见 | 同上模式 | ✅ 同上 |
| T1.7 | **不应显示 Manager 专属快捷操作** | `expect(page.getByText('批量评分')).not.toBeVisible()` | ✅ **能发现角色权限混淆**（Admin 被错误渲染了经理按钮） |
| T1.8 | **不应显示 Employee 专属快捷操作** | `expect(page.getByText('进入自评')).not.toBeVisible()` | ✅ **同上** |
| T1.9 | **不应显示 Peer 专属快捷操作** | `expect(page.getByText('进入协作评分')).not.toBeVisible()` | ✅ **同上** |

#### Bug 发现能力评估

| 能力 | 评估 |
|------|------|
| **角色渲染隔离** | **高**：如果 `DashboardView.vue` 中 `userRole` 判断逻辑错误（如把 admin 误判为 manager），`.not.toBeVisible()` 断言会立即失败。 |
| **API 异常检测** | **中**：如果后端 `/dashboard` 相关 API 返回 500，统计卡片不会渲染，`.toBeVisible()` 会超时失败。 |
| **数值正确性** | **未覆盖**：没有断言统计数值（如"员工总数=5"），因为 E2E 不应依赖具体数据量。 |

#### 潜在不足

- 未测试 Admin 仪表盘是否包含**快捷操作入口**（Admin 本身无专属快捷操作，这一点已覆盖，但未正向验证"快捷操作区域是否存在"）。
- 未测试仪表盘数据的**实时性**（如新增员工后统计是否自动刷新）。

#### Bug 发现能力评估

| 能力 | 评估 |
|------|------|
| **页面准入** | **低**：仅验证了页面可访问和基础元素存在。 |

#### 潜在不足

- 当前用例仅属于**"准入性测试"**（能进入页面），缺乏**"操作性测试"**（点击、填写、提交、验证结果）。

## 五、能发现的 Bug vs 不能发现的 Bug

### ✅ 能发现的 Bug

| 编号 | Bug 类型 | 发现方式 |
|------|---------|---------|
| B1 | Admin 被错误渲染了其他角色的专属按钮 | `.not.toBeVisible()` 断言失败 |
| B2 | Admin 无法访问本应拥有权限的页面（如 `/employees` 被路由守卫拦截） | `toHaveURL` 断言失败 |
| B3 | 页面白屏或 Vue 组件未渲染 | `.toBeVisible()` 超时失败 |
| B4 | 后端仪表盘 API 返回错误（500/401） | 统计卡片不渲染导致超时 |
| B5 | 前端路由配置错误（如 `/config` 被误配为 admin 不可访问） | `toHaveURL` 断言失败 |

### ❌ 不能发现的 Bug（当前用例盲区）

| 编号 | Bug 类型 | 影响 | 建议补充场景 |
|------|---------|------|------------|
| B6 | 系统配置表单交互缺陷：修改维度权重后保存失败 | Admin 核心工作受阻 | 补充"修改维度权重并保存"场景 |
| B7 | Tab 标签混淆（如 P1-15 已修复的问题回退） | 用户误判功能位置 | 补充"切换 Tab 并验证标签文本"场景 |
| B8 | 员工管理新增/编辑/删除操作失败 | 组织管理功能不可用 | 补充"新增员工并验证列表刷新"场景 |
| B9 | Excel 批量导入格式错误无提示 | 数据导入体验差 | 补充"上传错误格式 Excel 并验证提示"场景 |
| B10 | 强制分布特批审批链路断裂 | Admin 最终审批权失效 | 补充"强制分布特批审批"场景 |
| B11 | 审批链配置保存后未生效 | 审批流程混乱 | 补充"修改审批链并验证"场景 |
| B12 | 已归档数据无法解冻修改 | 数据治理功能不可用 | 补充"归档数据解冻"场景 |
| B13 | 角色权限分配后未生效 | 权限管理失效 | 补充"分配角色后验证被分配用户视图"场景 |

## 六、结论与建议

### 结论

当前 Admin 的 E2E 测试完成了**"角色准入验证"**（能登录、能看仪表盘、能进页面），但**远未达到"业务场景验证"**的标准。对于一个系统管理员角色，4 个场景、9 个测试点是不足够的。

### 建议补充的优先级场景（按业务价值排序）

| 优先级 | 建议补充场景 | 预期复杂度 | 预估耗时 |
|--------|------------|-----------|---------|
| **P0** | 系统配置：切换 Tab → 修改维度权重 → 保存 → 刷新验证回显 | 中 | 2 人时 |
| **P0** | 员工管理：点击新增 → 填写表单 → 提交 → 验证列表出现新员工 | 中 | 2 人时 |
| **P1** | 系统配置：修改审批链（增删审批人）→ 保存 → 验证新审批链生效 | 中 | 1.5 人时 |
| **P1** | 员工管理：上传错误格式 Excel → 验证前端错误提示 | 低 | 1 人时 |
| **P2** | 部门管理：拖拽排序部门 → 验证排序生效 | 高（需模拟拖拽） | 2 人时 |
| **P2** | 强制分布特批：进入审批页面 → 特批一条记录 → 验证状态变化 | 高（需准备数据） | 3 人时 |
