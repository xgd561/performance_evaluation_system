## 一、跨部门协作人工作职责总览（PRD 来源）

| 序号 | 职责领域 | 具体工作内容 | PRD 章节 |
|------|---------|------------|---------|
| 1 | **协作评分** | 对 HR 分配的协作员工进行"工作能力"维度评分（0-100 分），系统提供评分锚点说明 | 4.4, 业务流程图 |
| 2 | **查看参考评分** | 评分时可查看该员工的自评和上级评分数值作为参考 | 4.4 |
| 3 | **待办管理** | 查看自己的协作评分待办列表、任务状态、截止时间 | 业务流程图 |

**关键约束**：
- 协作人仅评分"工作能力"一个维度（权重 20%）
- 协作人无自评、无绩效查看、无申诉权限
- 协作人仅能看到自己被分配到的评分任务

| B-7 | 空状态（无待办任务） | 登录 → 进入协作评分待办（ peer001 无分配任务时） | `el-empty` "暂无待办协作评分任务"提示可见 | ✅ 已覆盖 |

## 八、E2E 测试原则（协作人角色补充）

> **核心原则：角色职责与账号严格对应，测试场景必须复现真实协作人操作路径。**

### 1. 账号-职责映射规范

| 职责操作 | 应使用账号 | 说明 |
|---------|-----------|------|
| 提交协作评分 | peer001 | PRD 定义：跨部门协作人评分 |
| 查看协作评分待办 | peer001 | PRD 定义：协作人查看自己的待办 |
| 分配协作关系（前置） | hr001 | 属于 HR 职责，Peer 测试中可作为前置数据准备 |
| 创建考核周期（前置） | admin | 属于系统管理员职责 |
| 发起考核（前置） | hr001 | 属于 HR 职责 |
| 员工自评（前置） | emp001 | 属于员工职责，供协作人查看参考 |
| 上级评分（前置） | mgr001 | 属于直属上级职责，供协作人查看参考 |

### 2. 测试脚本实现规范

1. **前端操作**：必须使用 `peer001` 账号登录浏览器（`peerLogin(page)`）。
2. **API 数据准备**：如果测试需要前置的协作关系数据（如 HR 分配 peer001 为 emp001 的协作人），可使用 `hr001` 或 `admin` token 通过 API 创建，但必须在测试代码注释中说明为什么该步骤不由当前 Actor（协作人）完成。
3. **参考评分前置**：为了让协作人能看到"员工自评参考"和"上级评分参考"，需要前置完成 emp001 的自评和 mgr001 的上级评。这些操作本身已有对应的 E2E 测试覆盖（Employee 和 Manager 测试套件）。
4. **反模式**：严禁在 Peer 场景测试中隐式使用 `admin`、`hr`、`employee` 或 `manager` 账号完成协作人职责范围内的操作（如提交协作评分）。
