# HR（绩效专员/人事管理员）E2E 使用场景扩充清单 — 已实施

> 目标：根据 PRD 中的工作职责，全面梳理 HR 应覆盖的 E2E 使用场景，形成场景-职责覆盖矩阵。

> **状态**：5/5 测试全部通过，但均为准入性查看，操作验证严重不足。

## 一、HR 工作职责总览（PRD 来源）

| 序号 | 职责领域 | 具体工作内容 | PRD 章节 |
|------|---------|------------|---------|
| 1 | **发起考核** | 在系统配置完成后，发起考核并选择参与员工，系统生成评分表 | 业务流程图第 5 节 |
| 2 | **监控进度** | 跟踪考核各阶段（自评、上级评、协作评、汇总、审批）的完成情况 | 业务流程图 |
| 3 | **处理申诉** | 员工对绩效结果有异议时，复核并决定维持或修改结果 | 业务流程图 |
| 4 | **汇总分析** | 进行分数汇总、加权计算、绩效等级划分后的数据分析 | 4.6, 6.2 |
| 5 | **生成分报表** | 导出 Excel 报表，供管理层审阅 | 6.2 |
| 6 | **审批参与** | 在绩效结果审批流程中，作为三级审批链的一环（HR 负责人） | 4.8, 业务流程图 |
| 7 | **KPI 调整审批** | 直属上级提出的 KPI 动态调整申请，需经"部门负责人 + HR"审批 | 4.2 |
| 8 | **异常评分处理** | 标记无效评分（如某协作人全部给同分） | 4.4 |
| 9 | **强制分布特批审批** | 特批审批链：部门负责人 → HR 负责人 → 系统管理员/总经理 | 4.5.1 |
| 10 | **员工信息导入** | 导入/同步员工信息（姓名、工号、部门、岗位、直属上级、考核关系） | 6.1 |

## 七、E2E 测试原则（2026-07-01 补充）

> **核心原则：角色职责与账号严格对应，测试场景必须复现真实用户操作路径。**

### 2. 测试脚本实现规范

1. **前端操作**：必须使用该场景对应角色的账号登录浏览器（`hrLogin(page)`、`mgrLogin(page)` 等）。
2. **API 数据准备**：同样遵循职责映射，不允许为了图方便用 `admin` token 替代其他角色完成其职责范围内的操作（如不能用 admin 发起申诉、不能用 admin 触发汇总计算）。
3. **例外情况**：如果某操作确实需要其他角色前置完成（如 admin 先创建周期，HR 再发起），应在测试代码注释中说明为什么该步骤不由当前 Actor 完成，并确保该前置操作本身也在对应角色的测试场景中得到覆盖。
4. **反模式**：严禁在"HR 场景测试"中隐式使用 `admin` token 完成 HR 职责范围内的 API 调用（如 `launchCycleViaApi`、`calculateScoresViaApi`、`assignPeerReviewerViaApi` 等），这会导致测试无法暴露后端权限配置错误。
