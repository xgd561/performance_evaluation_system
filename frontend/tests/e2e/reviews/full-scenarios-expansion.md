# 全场景 E2E 测试覆盖方案（基于业务流程图）

> 目标：基于绩效考核评分系统的完整业务流程图，设计全场景（正常流 + 异常流）的 E2E 测试覆盖方案，形成跨角色、跨阶段的全场景覆盖矩阵。
> 来源：`PRD_绩效考核评分系统_v1.0.md` 业务流程图 + 各角色场景扩充清单（Admin/HR/Employee/Peer/Manager）
> **状态**：基于各角色现有 E2E 覆盖，汇总全场景覆盖度。

## 一、业务流程图拆解（10 个核心节点）

```
[1] 系统管理员 → 配置考核周期 + 岗位 KPI 模板
            ↓
[2] HR → 发起考核 → 系统生成评分表
            ↓
[3] 员工 → 自评（填写各维度得分 + 自评评语）
            ↓
[4] 直属上级 → 上级评分（填写得分 + 综合评语）
            ↓
[5] 跨部门协作人 → 协作评分（如启用）
            ↓
[6] 系统 → 自动汇总 + 加权计算 + 等级划分
            ↓
[7] 直属上级 → 绩效面谈 → 记录面谈内容
            ↓
[8] 直属上级 → 部门负责人 → HR负责人 → 审批（通过/驳回）
            ↓
[9] 系统 → 发布结果 → 员工可查看
            ↓
[10] 员工 → 无异议 → 考核归档
       → 有异议 → 发起申诉 → HR 复核 → 维持/修改结果
```

### 业务流程中的异常分支

```
[1a] 系统管理员 → 配置考核周期 → 取消/归档/解冻周期
[2a] HR → 发起考核 → 无员工可选 / 取消考核
[3a] 员工 → 自评 → 保存草稿 / 逾期未自评 / 空值提交 / 分数越界
[4a] 经理 → 上级评分 → 与自评差异>20分触发确认 / 保存草稿 / 空值提交
[5a] 协作人 → 协作评分 → 无待办任务 / 空值提交 / 分数越界
[6a] 系统 → 汇总计算 → 强制分布触发特批 / 异常评分（同分）
[7a] 经理 → 绩效面谈 → 无记录 / 空状态
[8a] 审批 → 驳回 → 绩效面谈 → 重新评分 → 重新审批
[9a] 系统 → 发布结果 → 强制分布未通过需特批 → 重新发布
[10a] 员工 → 发起申诉 → 被驳回 → 再次申诉（按策略允许/不允许）
```

## 八、测试原则与规范（全场景补充）

### 1. 跨角色测试数据隔离

```typescript
// 推荐：每个 full-cycle 测试使用唯一周期名称，避免历史数据干扰
const cycleName = `全场景测试-${Date.now()}`
```

### 2. 状态机断言规范

```typescript
// 推荐：不仅断言提示文本，还要断言状态标签
await expect(page.getByText('自评中')).toBeVisible() // 周期状态
await expect(page.getByText('待上级评')).toBeVisible() // 记录状态
```

### 3. 多角色切换规范

```typescript
// 推荐：使用对应角色的 login 辅助函数，而非共用 admin token
await adminLogin(page)   // 步骤 1：Admin 创建周期
await hrLogin(page)      // 步骤 2：HR 发起考核
await employeeLogin(page) // 步骤 3：Employee 自评
await managerLogin(page) // 步骤 4：Manager 评分
// ...
```

### 4. 完整流程测试的断言策略

| 阶段 | 断言重点 | 反模式 |
|------|---------|--------|
| 配置阶段 | 表单提交成功、数据库持久化 | 仅断言"成功"提示，不验证刷新后回显 |
| 发起阶段 | 周期状态变化、评分表生成 | 仅断言列表新增，不验证记录状态 |
| 评分阶段 | 分数正确提交、状态流转 | 仅断言提交成功，不验证下阶段可见性 |
| 汇总阶段 | 计算结果正确、等级分布合理 | 仅断言计算成功，不验证具体分数 |
| 审批阶段 | 审批状态变化、理由记录 | 仅断言按钮点击，不验证状态标签 |
| 发布阶段 | 结果可见、员工可查看 | 仅断言发布成功，不验证员工端显示 |
| 申诉阶段 | 申诉记录、状态流转、HR 处理 | 仅断言提交成功，不验证历史时间线 |
