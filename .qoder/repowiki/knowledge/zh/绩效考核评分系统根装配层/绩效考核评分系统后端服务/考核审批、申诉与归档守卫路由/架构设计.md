本模块由三个并列的 FastAPI `APIRouter` 组成，均挂载到应用根路由下：
- `approvals.py`：核心审批流，通过 `_get_approval_chain` 从 `SystemConfig` 读取可配置的角色链（默认 `direct_manager → dept_head → hr_head`），用 `_can_approve_as_role` / `_can_access_approval_detail` 校验当前用户是否匹配链上角色；状态变更统一委托 `app.utils.workflow_state_machine.WorkflowStateMachine.transition` 计算新状态，并配合 `ApprovalRecord.step_index` 记录多步进度。
- `appeals.py`：独立申诉流程，围绕 `AppealRecord` 模型实现创建、列表、详情、复核（`review`）与终局处理（`resolve`），并通过 `AssessmentRecord.appeal_record` JSON 字段回写申诉上下文，同时调用 `create_notification` 通知 HR 与申诉人。
- `archive_guard.py`：纯工具模块，暴露 `check_record_not_archived` / `check_cycle_not_archived` 两个前置守卫函数，被 approvals 与 appeals 在写入类接口中统一调用以拒绝已归档周期的修改。
依赖方向单向向外：本模块依赖 `app.models`、`app.auth`、`app.database`、`app.services.operation_logger`、`app.services.notification_service`、`app.utils.workflow_state_machine` 及同包下的 `employees._is_in_subordinate_chain`，不被其他业务模块反向引用。
