- 每个业务模块一个 `test_xxx.py` 文件，内部按功能分组为 `TestClass` 类，方法名以 `test_` 开头并附带对应 TC-XXX 编号注释。
- 共享夹具集中在 `scripts/conftest.py`，按 scope="session" 复用 client、各角色 token/headers 及 seeded_* 数据种子，避免重复登录和建库。
- 对外部依赖（FastAPI、SQLAlchemy、openpyxl）采用 try/except ImportError 包裹并在缺失时 `pytest.skip`，保证未实现阶段仍可运行测试框架。
- HTTP 断言统一走 `utils.assert_status_code` / `assert_json_field`，禁止在测试中散落裸 `assert resp.status_code == ...`。
- 创建资源时使用 POST 后回退到 GET 查询的幂等模式：若返回 409 则转为查询接口取已有记录，使测试可重复运行。
- 用例编号遵循 TC-<MODULE>-NNN 规范，Markdown 文档与 Python 测试方法 docstring 双向标注同一编号以便追溯。
