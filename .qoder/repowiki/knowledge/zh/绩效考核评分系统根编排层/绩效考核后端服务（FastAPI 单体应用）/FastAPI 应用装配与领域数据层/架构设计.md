模块按单向依赖划分为四层：
- 应用装配层（main.py）：创建 FastAPI 实例，注册 CORSMiddleware、AuditLogMiddleware、UnifiedResponseMiddleware 与全局 HTTPException/RequestValidationError 处理器；通过 APIRouter(prefix="/api/v1") 聚合 auth、employees、departments、cycles、kpi_templates、config、dashboard、appeals、scores、reports、approvals、interviews、peers、logs、notifications、health 等子路由，同时挂载无前缀 direct_api 以兼容测试。
- 基础设施层（database.py）：基于 SQLAlchemy create_engine 创建 SQLite engine（文件位于仓库根 data/db/performance_evaluation.db，connect_args={"check_same_thread": False}），暴露 SessionLocal、get_db() 生成器与 init_db() 建表函数。
- 领域模型层（models.py）：以 declarative_base 定义 Department / Position / Employee / User / AssessmentCycle / KpiTemplate / AssessmentRecord / ScoreDetail / ApprovalRecord / CycleEmployee / PeerReviewer / OperationLog / AppealRecord / InterviewRecord / SystemConfig / ScoreDraft / Notification / PeerReviewTask 等 ORM 实体，使用 ForeignKey + relationship 表达组织与考核流程关系，JSON 列承载配置快照。
- 接口契约层（schemas.py）：用 Pydantic v2 BaseModel 定义 Create/Update/Out 三态 DTO，Out 类通过 class Config: from_attributes = True 直接映射 SQLAlchemy 对象，复杂业务约束通过 @field_validator / @model_validator(mode='after') 集中声明（KPI 权重总和=100、等级区间连续不重叠、截止时间递增顺序）。
- 依赖注入层（dependencies.py）：在 app.auth.get_current_user / require_role 之上封装 get_current_active_user，统一复用 get_db 会话依赖。
启动阶段通过 @app.on_event("startup") 执行 init_db → _migrate_db（基于 inspector 对比 Base.metadata 与现有表结构，自动 ALTER TABLE 补齐缺失列，跳过 NOT NULL 且无标量默认值的列）→ 幂等 seed admin/hr/mgr/emp/peer/testuser 等测试账户。
