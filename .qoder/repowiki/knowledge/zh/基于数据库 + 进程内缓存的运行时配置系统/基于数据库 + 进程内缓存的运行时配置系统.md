## 1. 采用的方案

本仓库没有使用 `python-dotenv`、Pydantic Settings、YAML/TOML 等外部配置框架。运行时配置采用**“数据库持久化 + 进程内 dict 缓存”**的两层模式：
- 所有可编辑的系统配置（评分等级规则、维度权重、评分人权重、小部门豁免、协作评分开关等）以 JSON 文本形式持久化在 SQLite 的 `system_configs` 表中。
- 每次读取先查模块级 `_CACHE: dict[str, Any]`，未命中再落库；写入后通过 `invalidate_config_cache(key)` 失效对应 key。
- 前端侧的常量（如评分锚点）通过后端 `/api/v1/config/scoring-anchors` 接口下发，与后端 `app/core/constants.py` 中的 `SCORING_ANCHORS` 保持同步。

JWT 密钥、数据库连接串等启动期参数目前以 Python 常量硬编码在代码中（见 `backend/app/auth.py`、`backend/app/core/security.py`、`backend/app/database.py`），尚未接入 `.env`/环境变量注入通道——尽管文档脚本 `scripts/update_sections_9_10.py` 明确声明了“禁止硬编码密钥，必须通过环境变量或 .env 文件注入”的规则。

## 2. 关键文件

- `backend/app/models.py` — `SystemConfig` 模型（`system_configs` 表，字段 `key`(唯一)、`value`(JSON Text)、`updated_at`）。
- `backend/app/services/config_service.py` — 配置服务层，提供 `_get_or_create_config` / `_fetch` / `clear_config_cache` / `invalidate_config_cache` 以及各业务配置的 getter（`get_grade_rules`、`get_dimension_weights`、`get_reviewer_weights`、`get_small_dept_exemption`、`get_peer_review_enabled`）。
- `backend/app/routers/config.py` — 暴露 `/config/*` REST API（GET/PUT 成对），负责入参校验、调用 service、写回 DB、失效缓存并记录审计日志。
- `backend/app/core/constants.py` — 前后端共享的评分锚点常量，注释要求“修改时同步更新 frontend/src/constants/scoringAnchors.js”。
- `frontend/src/constants/scoringAnchors.js` — 前端侧评分锚点常量，与后端 `SCORING_ANCHORS` 保持一致。
- `backend/app/auth.py`、`backend/app/core/security.py`、`backend/app/database.py` — JWT SECRET_KEY、ALGORITHM、SQLALCHEMY_DATABASE_URL 等启动期常量的当前硬编码位置。
- `backend/tests/test_config_service.py`、`backend/tests/test_config.py`、`backend/tests/test_config_integration.py` — 覆盖配置缓存、CRUD 与集成场景。

## 3. 架构与约定

### 3.1 数据模型
`SystemConfig` 是通用的键值存储表，所有业务配置统一通过 `key` 区分：
| key | 默认值 | 用途 |
|---|---|---|
| `grade_rules` | `{A/B/C/D: {min,max,ratio_limit}}` | 强制分布等级区间与比例上限 |
| `dimension_weights` | `{performance:0.6, ability:0.2, attitude:0.2}` | 维度权重（整数百分比，getter 会把 ≤1 的浮点转为百分数，即 60/20/20） |
| `reviewer_weights` | `{performance:{self:30,manager:70,peer:0}, ability:{self:20,manager:60,peer:20}, attitude:{self:10,manager:50,peer:40}}` | 各角色在各维度的加权比例（每个维度 self+manager+peer=100） |
| `small_dept_exemption` | `{enabled:true, threshold:5}` | 小部门豁免阈值 |
| `peer_review_enabled` | `{enabled:true}` | 协作评分功能开关 |
| `approval_chain` | （由 `routers/approvals.py` 直接读写） | 审批链配置 |

> **权重默认值权威口径**：`config_service.get_dimension_weights`（60/20/20）与 `config_service.get_reviewer_weights`（业绩 30/70/0、能力 20/60/20、态度 10/50/40）是**唯一来源**。`routers/cycles.py` 创建周期时直接取上述值写入快照（请求 `weights` 为空时）；前端 `CycleList.vue` 不再硬编码；`models.py:76-77` 的列默认值仅为绕过路由直接建档（脚本/测试）的兜底，已对齐为同值（0.3/0.7/0.0、0.2/0.6/0.2、0.1/0.5/0.4）。回归用例：`backend/tests/test_cycle_default_weights.py`。

### 3.2 缓存策略
- 模块级全局 `_CACHE` 字典，key → 已解析的 Python 对象。
- 读路径：`_fetch(db, key, default_json)` → 命中则返回，否则 `_get_or_create_config` 从 DB 取或插入默认值，`json.loads` 后写入缓存。
- 写路径：路由层直接操作 `SystemConfig.value = json.dumps(payload)`，然后调用 `config_service.invalidate_config_cache(key)` 使旧缓存失效。
- 测试可通过 `config_service.clear_config_cache()` 清空全部缓存。

### 3.3 权限与审计
- 所有写接口均通过 `Depends(require_role("admin"))` 保护（仅 `/config/peer-review-enabled` 的 GET 允许 admin/hr/manager）。
- 每次写操作通过 `log_operation(..., target_type="system_config", ...)` 记录 old_value/new_value 到 `operation_logs` 表。

### 3.4 前端配置获取
- 前端不直接访问 `system_configs` 表，而是通过后端 `/api/v1/config/*` 接口拉取。
- 评分锚点作为只读参考数据，由后端 `constants.SCORING_ANCHORS` 经 `/config/scoring-anchors` 下发给前端，前端本地也有一份 `scoringAnchors.js` 副本，二者需保持同步（见 constants.py 顶部注释）。

## 4. 约定与约束

- **配置持久化位置**：所有运行时配置统一存储在 SQLite `system_configs` 表的 `key/value` 列，值以 JSON 字符串序列化（`config_service._fetch` 中 `json.loads`）。新增配置类型需在 `config_service.py` 增加 getter，并在 `routers/config.py` 暴露 GET/PUT 端点。
- **缓存一致性**：任何对 `SystemConfig.value` 的直接写入（包括 `approvals.py` 中对 `approval_chain` 的操作）都必须配合 `config_service.invalidate_config_cache(key)`，否则后续请求可能读到旧值。该约束由单元测试 `test_config_service.py` 验证。
- **必填等级**：更新 `grade_rules` 时必须包含 A/B/C/D 四个等级，否则抛出 422（`routers/config.py` 第 57-62 行）。
- **维度权重总和**：更新 `dimension_weights` 时各维度之和必须等于 100，否则抛出 422（`routers/config.py` 第 117-122 行）。
- **小部门豁免阈值范围**：`threshold` 必须在 1–50 之间，且 `enabled` 必须为布尔值（`routers/config.py` 第 205-222 行）。
- **评分锚点前后端同步**：`backend/app/core/constants.py` 的 `SCORING_ANCHORS` 与 `frontend/src/constants/scoringAnchors.js` 必须保持一致，修改时需同步更新两端（见 constants.py 顶部注释）。
- **密钥与环境变量**：项目文档脚本 `scripts/update_sections_9_10.py` 明文规定“禁止硬编码密钥：JWT 密钥、数据库密码必须通过环境变量或 `.env` 文件注入”，但当前实现仍把 `SECRET_KEY` 和 `SQLALCHEMY_DATABASE_URL` 硬编码在 Python 源码中，尚未落地该约束。
- **无外部配置文件**：仓库未发现 `.env`、`.yaml`、`.toml`、`application.properties` 等外部配置源；FastAPI 应用本身也未加载 dotenv 或 Pydantic Settings。
