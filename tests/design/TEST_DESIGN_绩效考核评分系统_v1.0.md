## 1. 测试策略总览

### 1.1 测试目标

本测试设计以 **用户角色 + 使用场景** 为核心维度，覆盖绩效考核系统全流程。不仅验证功能正确性，更关注多角色交互的流畅性、异常场景的容错性、内部系统的安全性以及关键页面的性能表现。

### 1.2 测试范围

| 测试类型 | 覆盖范围 | 优先级 | 说明 |
|---------|---------|--------|------|
| **场景测试** | 按角色划分的端到端业务流程（含正向+逆向） | P0 | 场景测试已自然覆盖核心功能验证，不再单独拆分功能测试 |
| **交互体验测试** | 页面流畅度、操作友好性、异常提示清晰度 | P1 | 每个场景均需检查交互体验 |
| **安全测试** | 身份认证、权限隔离、数据防篡改、SQL/XSS 注入、密码安全 | P1 | 包含初始密码分发与首次登录安全 |
| **性能测试** | 页面加载、API 响应、并发评分、报表导出 | P1 | 关键页面与关键操作 |
| **兼容性测试** | 主流浏览器（Chrome/Edge/Firefox） | P2 | 核心功能兼容性 |

### 1.3 角色-场景矩阵

| 角色 | 核心使用场景 | 测试场景数 |
|------|------------|-----------|
| **系统管理员** | 系统初始化、密码分发、周期配置、KPI 模板维护 | 16 |
| **HR / 绩效专员** | 考核发起、进度监控、强制分布处理、申诉复核、报表导出 | 18 |
| **部门负责人 / 直属上级** | 下属评分、审批绩效、绩效面谈、查看团队趋势 | 14 |
| **跨部门协作人** | 协作评分待办处理 | 6 |
| **普通员工** | 自评提交、查看本人绩效、历史趋势查询、发起申诉 | 12 |
| **全角色通用** | 登录认证、首页仪表盘、消息通知、密码修改 | 8 |
| **安全与性能** | 渗透测试、并发测试、压力测试 | 10 |
| **合计** | — | **84** |

## 2. 场景测试设计（按角色）

### 2.1 系统管理员场景

#### 场景 A1: 系统冷启动初始化（正常场景）

| 测试项 | 测试内容 | 预期结果 | 交互体验检查点 |
|--------|---------|---------|--------------|
| A1-1 | 首次访问系统，创建管理员账号 | 账号创建成功，自动登录 | 是否有引导提示？表单校验是否实时？ |
| A1-2 | 下载员工批量导入模板 | 下载 `.xlsx` 文件，包含表头+示例数据 | 是否提供「空模板」和「带示例模板」两个选项？ |
| A1-3 | 上传填写好的员工 Excel | 解析成功，显示预览表格 | 进度条是否显示？解析时间是否合理（<3秒）？ |
| A1-4 | 预览校验通过，确认导入 | 员工数据入库，自动创建部门/岗位 | 导入结果是否清晰展示（成功X条/失败Y条）？ |
| A1-5 | 核对导入结果，补充考核关系 | 直属上级关系正确建立 | 直属上级为空的员工是否有醒目提示？ |

#### 场景 A1.5: 冷启动密码初始化与安全分发（正常场景）

| 测试项 | 测试内容 | 预期结果 | 交互体验检查点 |
|--------|---------|---------|--------------|
| A1.5-1 | 管理员为员工设置初始密码 | 系统保存初始密码（bcrypt哈希），不存明文 | 密码输入框是否支持「显示/隐藏」切换？ |
| A1.5-2 | 系统随机生成初始密码 | 生成为8位随机串（大小写+数字），管理员可查看 | 是否提供「重新生成」按钮？ |
| A1.5-3 | 员工首次登录（使用初始密码） | 登录成功，但**强制跳转**密码修改页 | 是否显示提示「首次登录，请修改密码」？任何页面是否均不可访问？ |
| A1.5-4 | 员工修改初始密码为新密码 | 修改成功，自动重新登录，进入首页 | 新密码是否要求复杂度（8-16位，大小写+数字）？是否有密码强度条？ |
| A1.5-5 | 管理员导出员工初始密码清单 | 生成加密文件或打印友好格式，含姓名+工号+初始密码 | 导出文件是否支持密码保护（如ZIP加密）？ |

#### 场景 A1.6: 冷启动密码初始化与安全分发（异常场景）

| 测试项 | 测试内容 | 预期结果 | 交互体验检查点 |
|--------|---------|---------|--------------|
| A1.6-1 | 员工首次登录后跳过密码修改（直接关闭页面） | 再次登录时仍强制跳转密码修改页 | 未修改密码时 Token 是否限制访问任何业务接口？ |
| A1.6-2 | 员工修改密码时输入与初始密码相同的新密码 | 系统拦截，提示「新密码不能与初始密码相同」 | 错误提示是否清晰？ |
| A1.6-3 | 员工修改密码时输入弱密码（如 12345678） | 系统拦截，提示「密码复杂度不足」 | 密码强度条是否实时反馈？ |
| A1.6-4 | 管理员尝试查看已保存的员工密码 | 系统仅显示密码状态（已设置/未设置），不显示明文 | 是否有「密码已加密，不可查看」的明确提示？ |
| A1.6-5 | 初始密码泄露，员工账号被他人登录 | 系统记录异常登录IP，员工登录后提示「上次登录IP异常」 | 是否支持登录后强制再次修改密码？ |

## 8. API 接口功能测试设计（全量接口覆盖）

### 8.1 设计原则

本章节对技术方案文档中定义的所有 API 接口进行系统化功能测试设计。每个接口的测试覆盖以下维度：

| 测试维度 | 说明 | 测试方法 |
|---------|------|---------|
| **正向参数** | 符合接口规范的合法参数 | 验证返回状态码 200，数据结构正确，数据库状态正确变更 |
| **必填参数缺失** | 逐个移除必填参数 | 验证返回状态码 422，提示具体缺失字段 |
| **参数类型错误** | 字符串传数字、数字传字符串、布尔传字符串等 | 验证返回状态码 422，提示参数类型错误 |
| **参数格式错误** | 邮箱格式错误、日期格式错误、JSON 格式错误 | 验证返回状态码 422，提示格式错误 |
| **参数边界值** | 最大值、最小值、空字符串、超长字符串、超大数据 | 验证边界内通过，边界外拦截 |
| **非法字符** | SQL 注入、XSS 脚本、特殊符号、emoji、换行符 | 验证安全过滤，无注入执行，无 500 错误 |
| **权限校验** | 无 Token、错误 Token、过期 Token、低权限角色访问高权限接口 | 验证返回 401/403，无数据泄露 |
| **状态码验证** | 接口文档约定的所有状态码 | 每个状态码至少验证一次 |
| **幂等性** | 重复提交同一请求 | 验证数据库无重复数据，或第二次返回已存在提示 |
| **并发冲突** | 同时修改同一资源 | 验证无脏数据，或后提交者收到冲突提示 |

### 8.15 通用异常与幂等性测试（跨所有接口）

| 测试项 | 测试内容 | 涉及的接口示例 | 预期结果 |
|--------|---------|--------------|---------|
| **通用-401** | 无 Authorization Header | 任意需要认证的接口 | 401 Unauthorized |
| **通用-401** | 伪造/篡改 JWT | 任意需要认证的接口 | 401 Unauthorized |
| **通用-401** | 过期 JWT | 任意需要认证的接口 | 401 Unauthorized + 刷新提示 |
| **通用-403** | 低权限角色访问高权限接口 | employee 访问 `/admin/config` | 403 Forbidden |
| **通用-403** | 访问非本人/非下属数据 | A经理查看B经理下属 | 403 Forbidden |
| **通用-404** | 资源不存在 | 不存在的 record_id/cycle_id/employee_id | 404 Not Found |
| **通用-422** | 必填参数缺失 | 移除任意必填字段 | 422 Unprocessable Entity + 具体字段提示 |
| **通用-422** | 参数类型错误 | 字符串传数字字段 | 422 Unprocessable Entity |
| **通用-409** | 重复提交（幂等性） | 重复调用创建/提交接口 | 409 Conflict 或幂等成功（根据业务设计） |
| **通用-429** | 请求频率限制 | 短时间内大量请求登录接口 | 429 Too Many Requests |
| **通用-500** | 非法字符触发异常 | SQL 注入/XSS 作为参数 | 不返回 500，应返回 400/422 并记录日志 |
| **通用-502/504** | 服务不可用/超时 | 后端服务宕机/网络超时 | 前端友好提示「服务暂时不可用，请稍后重试」 |
